# ONOFF CROSSFIT

온오프짐 전용 반응형 회원 앱. 기본 운영 주소는 https://nuclearstark.github.io/Onoffgym/ 이며 GitHub Pages 프런트와 대표 소유 Supabase를 사용한다.

## 로그인과 회원 관리

이메일·비밀번호·실명으로 가입하고 운영자가 승인해야 회원 화면에 접근한다. 가입 이메일 인증은 생략한다. Supabase의 **Confirm email OFF** 설정이 확인되지 않으면 앱은 가입 요청을 보내지 않는다. 이메일 계정 소유가 인증된 것으로 간주해 권한을 부여하지 않는다. 첫 운영자는 계정 생성 후 실제 회원 UUID를 확인하여 명시적으로 지정한다. 누구나 먼저 가입해서 운영자가 되는 기능은 없다.

로그인은 Supabase SDK가 유지·갱신한다. 승인 대기는 자동 갱신되며, 계정별 상태와 역할은 매번 서버가 확인한다. 비밀번호 재설정은 이메일 링크 → `auth-callback.html` → 새 비밀번호 입력 순서다. URL 설정과 실제 SMTP 발송 연결이 필요하다. 회원 탈퇴는 현재 비밀번호 재확인, 전체 세션 해제, Auth 계정의 하드 삭제와 개인 데이터 cascade를 사용한다. 마지막 승인 운영자는 다른 승인 운영자를 지정하기 전에 탈퇴·권한 해제할 수 없다.

## 데이터와 알림

Supabase 운영 앱은 수업·회원·운동 기록·1RM·출석·회원권·게시판을 서버에 저장한다. `?preview=1#home`은 실제 서버와 분리된 브라우저 예시 앱이다. 기존 owner-private Sites 미리보기는 이전 D1 백엔드를 유지하며 Supabase와 데이터가 합쳐지지 않는다.

웹 푸시는 알림을 허용한 기기에 발송하며 매분 서버 큐를 처리한다. 회원 가입 시 pending 회원과 중복 없는 승인 요청을 함께 생성한다. 승인 요청은 승인 운영자 중 해당 알림을 켠 기기에만 보내고 실제 전송 전 역할·신청 상태를 다시 확인한다. 공지·운동 공개 알림, 운영자 문구 작성·자기 기기 시험·이력을 지원한다. 기기 잠금 화면 수신은 실기기 시험으로 별도 확인한다.

모든 공개 앱 데이터 API는 Supabase Auth로 사용자를 검증한다. 앱 테이블의 직접 브라우저 접근과 RPC 호출은 허용하지 않는다. 개인 이름·이메일·JWT의 사용자 수정 가능 metadata로 역할을 결정하지 않는다. 서비스 비밀 키는 서버에만 둔다.

## 수업과 화면

- 공개 시각은 한국 시간 기준 운영 설정(기본 전날 22:00)을 사용하고 서버가 비공개 운동을 걸러낸다.
- XLSX 양식·예시 다운로드, 업로드 검증·미리보기·덮어쓰기 확인, 동작별 유튜브 링크를 지원한다.
- 출석은 버튼으로 하루 한 번 처리하고 횟수권은 하루 1회 차감한다. GPS는 사용하지 않는다.
- 수요일은 WOD만 표시한다. 휴강일과 오픈짐만 있는 날은 홈 시간표를 숨기며 하단 메뉴는 고정한다.
- TV는 4자리 암호, 가로 기본·운영자가 선택한 세로 방향, 수업별 색상, 긴 내용 페이지 전환을 지원한다.

## 개발과 검증

- `npm test`: 검증·API 권한·회원권·푸시·계정 처리 테스트.
- `node --test --test-isolation=none tests/*.test.mjs`: 각 테스트 결과를 개별 표시.
- `node scripts/dev.mjs`: 로컬 D1 호환 SQLite 미리보기. 개발용 쿠키는 운영 코드에서 사용하지 않는다.
- `npm run build:backend`: `supabase/functions/onoff-api/index.ts` 생성.
- `npm run build:pages`: 공개 Supabase 설정을 넣은 `pages-dist/` 생성. 전체 JS/CSS 버전을 매긴다.
- `npm run build`: 기존 Sites Worker, 웹 자산·D1 마이그레이션을 `dist/`에 생성.
- `python scripts/make-template.py`: XLSX 양식·예시 생성(openpyxl 필요).

SQL 검증은 `supabase/tests.sql`, `supabase/push-tests.sql`, `supabase/email-tests.sql`이며 실제 서비스 역할·트리거·cascade를 검증한 뒤 모두 rollback한다. 브라우저 모의 테스트가 실제 메일 수신·회원의 기기 간 동기화·실제 TV 동작을 대신하지 않는다.

## 배포와 운영 문서

GitHub main push 시 검증 후 Pages에 배포한다. Sites 미리보기는 소스 커밋과 동일하게 빌드한 아카이브를 배포하고 기존 비공개 접근 범위를 유지한다. Supabase Edge 함수와 SQL 마이그레이션은 별도로 적용한다.

- [GitHub 이전 준비](docs/github-이전준비.md) · `npm run handover:plan`으로 대상 미정 상태 검사, `-- --owner 대표아이디`로 새 주소 계획 확인(실제 이전 없음).
- [대표·운영자 인수인계](docs/운영자-인수인계.md)
- [Supabase 연결](docs/supabase-connection.md)
- [테스트 체크리스트](docs/handover-test-plan.md)

실제 메일 발송, 첫 운영자 지정, 개인정보 안내의 시행일·위탁·백업 보관 정책, 실제 휴대폰 수신은 설정/실기기 확인이 필요하다. 별도 순위 마감·집계 정책은 기존 체크리스트에 따른다.

## 타이머·ACC·운동 영상

- 상단 `타이머` 아이콘: AMRAP, FOR TIME, EMOM, TABATA, MIX. 시작 준비·구간 전환·종료 알림음, 일시정지·재개·초기화, 탭 이동 및 현재 세션 복원이 가능하다. iPhone의 화면 잠금/앱 백그라운드에서는 알림음이 보장되지 않는다. 푸시로 소리를 대신하지 않는다.
- ACC는 날짜별 선택 운동으로 홈 운동과 시간표 사이에 표시한다. 수업 공개 시각을 따르며 S1/S2와 TV에는 포함하지 않는다. 코치의 `acc.read/create/update/delete` 권한은 각각 기본 미부여다.
- 영상 대분류는 1RM 종목 분류와 독립적이다. 분류 삭제 시 동작을 선택한 분류로 옮기고, 동작 삭제는 영상 목록에서만 숨긴다. 기존 수업·1RM 기록을 삭제하지 않는다.
- 사진은 계정별 메모리 캐시 최대 24장이다. 55초 후 서버에서 접근권한을 재확인하며, 최대 약 6분 동안 보관한 바이너리를 재사용해 다운로드를 줄인다. 로그아웃·계정 변경·이용 중지 시 비운다. 디스크에 회원 사진을 영구 캐시하지 않는다.
- `?preview=1`로 실제 연결 앱을 우회할 수 없다. 로그인 화면의 예시 앱 진입과 개인 알림 설정의 중복 시험 발송은 제거했다. 별도 푸시 테스트 화면과 운영 발송기는 유지한다.
- `supabase/acc-video-tests.sql`은 합성 계정으로 권한·분류 이동·동작 숨김을 검증한 후 전체 롤백한다. `qa-next.cjs`는 API를 모킹한 모바일 브라우저 검증이며 실제 회원 요청이나 푸시를 보내지 않는다.

## 포인트 상점과 쿠폰

- 포인트 기능은 최초 설치 시 OFF, 출석/개인 운동기록 적립액은 각각 0P로 시작한다. 운영 관리 → 포인트 관리에서 적립액, 상품, 쿠폰용 4자리 비밀번호를 설정한 뒤 켠다. TV 비밀번호는 별도다.
- 출석과 본인이 새로 입력한 운동기록은 한국 시간 기준 각각 하루 1회 적립한다. 운영자의 타 회원 일괄 입력과 별도 1RM 등록은 적립하지 않는다. 기존 데이터에는 소급 적립하지 않으며, 기록 수정·삭제·재등록으로 같은 날 다시 받지 못한다.
- 교환은 잔액 차감과 쿠폰 발급을 한 DB 트랜잭션에서 처리한다. 교환·쿠폰 사용에는 재시도 ID를 사용한다. 쿠폰은 교환 당시의 상품명·포인트·횟수를 보관하며, 상품 삭제나 기능 OFF 이후에도 이미 발급한 쿠폰은 사용기한 내에 사용할 수 있다.
- 사용은 본인 쿠폰에만 허용하며, 매번 비밀번호 확인 후 1회 차감한다. 잘못된 비밀번호는 계정별 10분에 5회로 제한한다. 비밀번호는 서버의 bcrypt 해시로만 보관하며 프런트에는 내려주지 않는다.
- 회원카드와 쿠폰은 개인설정에서 좌우로 넘겨 볼 수 있다. 상점에서는 잔액·상품·적립/교환 내역·쿠폰을 확인한다. 포인트 설정/상품/최근 발급 쿠폰 관리는 운영자만 가능하다.
- `supabase/points-tests.sql`은 합성 계정으로 적립 중복·잔액 부족·교환/사용 재시도·소유권·PIN 제한·상품 변경/삭제·기능 OFF를 검증하고 전체 롤백한다. `qa-batch2.cjs`는 모든 회원 API를 모킹한다.
- 상단은 상점→타이머→개인설정이며 하단은 기존 메뉴 수에 맞춰 같은 폭으로 배치한다. 타이머의 AMRAP/EMOM/FOR TIME은 업카운트, 준비/TABATA는 다운카운트다. EMOM은 라운드마다 0부터 시작한다. 전체화면 API 미지원 시 앱 내부 전체화면으로 표시한다.

## 포인트 운영과 가입 알림 보완

- 운영자만 총 보유 포인트 상한, 적립 항목 추가·수정·삭제와 회원별 수동 지급을 관리한다. 자동 적립은 출석/개인 운동기록 각각 하루 한 번이며 B/T·WOD/S1·S2를 합친다. 추가 항목은 운영자 선택 지급용이다. 삭제한 자동 항목은 지급을 중지한다.
- 상한을 낮춰도 기존 잔액을 차감하지 않는다. 새로운 적립/수동 지급은 남은 한도까지만 지급하고 실제 지급액·사유를 기록한다. 수동 지급 재시도는 같은 요청 ID로 중복 처리하지 않는다.
- 새 쿠폰은 발급 순간부터 한국 시간 기준 달력상 1개월까지 사용한다(말일은 다음 달 말일로 맞춤). 기존 발급 쿠폰은 기존 조건을 보존한다. 만료된 쿠폰은 사용 차단하고 내역은 남긴다. 회원 탈퇴 시 포인트·쿠폰·사용 내역은 기존 FK cascade에 따라 함께 소멸한다.
- 운영 → 포인트 관리 → 체험하기는 가상 데이터만 사용한다. 출석/기록 적립, 교환, 비밀번호 사용, 시간 이동으로 만료를 체험하며 서버 호출·실제 포인트·실제 쿠폰 변경은 없다.
- 1RM 종목 삭제는 종목 ID를 보존한 보관 처리다. 관리/신규 선택 목록에서 제외하되 기존 기록과 이력은 유지한다. 운동 영상 분류에는 영향을 주지 않는다.
- 가입 신청 알림은 새 이벤트부터 승인 후에도 운영자에게 발송한다. 이전 알림은 기존 정책을 유지해 배포 후 과거 신청을 재발송하지 않는다. 수신 동의·운영자 역할·이용 상태는 발송 직전에 다시 확인한다.
- `supabase/point-rules-tests.sql`은 합성 계정/서비스 역할로 상한, 항목, 수동 지급, 쿠폰 기한, 탈퇴 정리를 검증 후 롤백한다. `qa-release3.cjs`는 브라우저 API를 모두 모킹한다. 실제 iPhone 키보드·화면 유지·잠금 중 소리는 실기기 확인이 필요하다.
