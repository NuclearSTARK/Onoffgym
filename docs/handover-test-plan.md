## 권장 준비

대표 소유의 카카오 개발자 앱과 Supabase 프로젝트를 만들고 개발자를 초대한다. 테스트가 끝날 때까지 개발자가 작업하고, 인수인계 시 대표가 관리자·복구 권한을 가진 상태를 확인한다. GitHub 저장소 소유권 이전이나 주소 변경 후에는 로그인 복귀 주소와 배포 경로를 다시 검사한다.

테스트 계정은 운영자 1명과 회원 2명 이상을 사용한다. 동명이인 시나리오를 위해 두 회원의 표시 이름을 같게 설정하되 계정은 다르게 만든다. 실제 휴대폰, PC와 체육관 TV로 함께 확인한다.

## 운영 정책을 확인할 항목

- 순위는 기록 입력·수정·삭제 및 참여 설정 변경에 따라 수시로 갱신한다. 마지막 수업까지 기록이 추가되면 당일 순위가 바뀔 수 있으며, 별도의 마감·확정 처리는 현재 요구사항에 없다. 동점 등수, 스케일 구분, 복합 기록의 집계 기준과 기기 간 갱신 방식은 구현 전에 확정한다.
- 현재 구현은 기존 승인 회원의 초기 설정을 위해 회원권 미등록 계정의 접근을 허용한다. 실운영 전 전체 회원권을 등록하거나, 미등록 계정의 접근 정책을 정하고 검증한다.
- 휴회는 실제 휴회 시작일부터 재개일까지의 한국 날짜 차이를 적용한다. 체육관에서 사용하는 휴회 최소·최대 기간과 소급 처리 정책을 확인한다.
- 실제 회원 데이터 공유, 카카오 세션, TV 공통 암호와 웹 푸시 예약 발송은 각 연결을 완료한 뒤 판정한다. 공개 데모의 동작만으로 실운영 통과 처리하지 않는다.

## 인수인계 완료 기준

1. 필수 항목을 실제 계정과 기기에서 확인하고, 실패 항목을 수정한 후 해당 흐름을 다시 검사한다.
2. 대표가 일상 운영 절차를 직접 한 번 이상 완료한다.
3. 서비스 소유권·배포 설정·복구 수단·백업과 운영 설명서를 대표에게 전달한다.
4. 오류 수정·기능 추가를 맡을 담당자와 처리 방법을 정한다.
