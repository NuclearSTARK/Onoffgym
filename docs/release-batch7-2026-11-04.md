# ONOFF 배포 — 커뮤니티·Named WOD·개인정보/계정 관리

## 변경 내용

- 커뮤니티 글자 크기를 키우고 게시글/댓글 작성자와 참여자 표시를 굵게 했다. 글 목록은 필터별 5개씩 가로 스와이프하며 새로 불러와도 현재 페이지를 유지한다. 팝업은 사진 로딩·폰트·키보드·가로 전환을 반영해 위치와 최대 높이를 다시 계산한다.
- 운동 번개가 여러 개면 문구를 흰색/연한 노란색으로 번갈아 표시하고 구분선/간격을 둔다. 기존 시작 후 30분 만료와 글 보존은 유지한다.
- 나의 기록의 1RM 아래에 Named WOD를 추가했다. 사용자 제공 두 사이트에서 추출한 54개 이름/운동 내용과 분류를 등록했다. 대분류는 웨이트·유산소·짐네스틱·혼합 순이다. Murph, DT, Fran, Cindy, Grace, Isabel, Helen, Annie, Diane, Elizabeth의 10개를 기본 표시한다.
- Named WOD의 시간 또는 라운드/횟수 방식은 종목별 설정이다. 원문의 AMRAP/EMOM 표현이 있는 11개는 라운드/횟수로 초기화했다. 운영자가 내용과 기록 방식을 검토/수정할 수 있다. 이미 기록이 있는 종목의 방식 변경은 차단해 과거 기록의 의미를 보존한다.
- 회원의 박스 본문은 운동 내용 팝업을 열고 기록 등록/이력은 별도 버튼이다. 본인 기록만 수정/삭제할 수 있고 최고 기록을 다시 계산한다. 운영 관리에서는 이름/배지/아이콘만 표시하며 내용은 추가/수정 폼에만 표시한다. 대분류와 종목을 추가/수정/삭제할 수 있고 기존 기록은 보존한다.
- 1RM 박스 본문은 체육관 내 상대 위치 그래프를 연다. 승인·공개 동의·순위 참여 회원 중 종목별 유효한 최고 기록을 회원당 1개만 집계한다. 동점은 같은 백분위다. 다른 회원 이름/개별 기록은 API에서 반환하지 않는다. 체중 보정 없이 중량으로 비교하며 비교 인원을 표시한다. 기록자 1명인 경우 백분위 대신 비교 인원 부족을 안내한다. 기존 +, 계산기, 이력은 유지한다.
- 승인 대기 목록의 이름/권한 표시와 승인/상세 버튼 간격을 조정했다. 30일 정리 기한과 대상 수를 표시하고 상세 화면에서 기한과 연령 확인 필요 상태를 볼 수 있다.
- 운영자 계정 삭제는 대상 이름 입력·확인 후 실행한다. 먼저 계정 이용을 차단하고 소유 사진, Auth 계정 및 관계된 개인 기록/포인트/쿠폰을 삭제한다. 요청 ID로 재시도를 처리하고 마지막 운영자 보호를 유지한다. 본인 탈퇴에서도 사진을 먼저 삭제한다. 삭제 완료 감사 식별자는 30일 후 일일 정리하며 이 작업은 회원 계정을 자동 삭제하지 않는다.
- 미승인 신청은 신청일, 승인 거절은 거절일로부터 30일 이내 운영자가 삭제하는 정책이다. 기존 승인/이용 중지 회원을 미승인 정리 대상에 소급 포함하지 않는다. 배포 자체는 실제 계정을 삭제하지 않는다.
- 개인정보처리방침 시행일/버전을 2026-11-04로 지정했다. 신규 가입과 기존 회원의 안내 화면에서 만 14세 이상/수집·이용 동의를 확인하고, 회원 간 공개는 선택 동의로 분리했다. 공개에 동의하지 않아도 수업·개인 기록을 이용할 수 있다. 공개하지 않은 회원의 기록/게시물/사진과 참여/댓글은 일반 회원 조회에서 제외한다. 새로운 승인 전 서버에서도 연령 확인/현행 방침 동의를 검사한다. 하단의 방침/문의 두 메뉴를 유지하며 이용약관은 추가하지 않는다.

## 검증

- Node 테스트 162개 통과: 종목/시간·라운드·횟수 검증, 최고 기록 수정/삭제, 동점·백분위, 서버 권한·소유권·명시적 확인, 가입 연령/동의 정보, 삭제 준비/사진/로그인 계정 삭제 순서 및 실패 시 재시도 포함.
- `qa-batch7.cjs`: 5개 가로 페이지, 커뮤니티 폰트와 사진 팝업/키보드, 다중 번개 색상, Named WOD 배치·기본10개·내용·분/초와 AMRAP·기록 CRUD·관리/분류, 1RM 그래프와 기존 추가 버튼, 320px 승인 대기, 운영자 삭제 모의 API, 개인정보 재안내와 선택 공개를 검증했다.
- `qa-release4.cjs`, `qa-audit.cjs`, `qa-storage.cjs`, `qa-collected.cjs`, `qa-batch6.cjs` 회귀 통과. 브라우저 검사는 Chromium 모의 환경이며 실물 iPhone/Android/TV 검사는 별도다.
- `supabase/batch7-tests.sql`을 합성 Auth/회원/기록/쿠폰/사진 메타데이터로 실행하고 전부 롤백했다. 실제 회원 삭제·포인트 초기화·쿠폰 사용·시험 알림/메일 발송 없음.
- 마이그레이션/Edge v22 배포 후 54종·기본10종·Named 기록 0개·실제 계정 삭제 요청 0개 및 익명 접근 차단을 확인했다. 새 보안 경고 없음. 기존 유출 비밀번호 보호 비활성화 경고는 유지하며 Auth/TV 암호 설정은 바꾸지 않았다.
- 테스트 SQL에서 Auth 내부 DB 역할로 직접 전환하는 권한은 도구에 없어 그 검사는 제외했다. 실제 SDK 삭제 호출 순서는 모의 API로, FK/삭제 트리거는 롤백 SQL로 각각 확인했다.

## 개인정보 운영자가 추가 확인할 사항

확인한 사실은 Supabase 프로젝트의 서울(ap-northeast-2) 리전과 무료 요금제다. 현재 도구는 SMTP/메일 훅 설정이나 제공사의 전체 백업/지원 접근 계약 설정을 조회하지 못하며 운영자도 별도 SMTP 사용 여부를 알지 못한다고 답했다. 따라서 특정 메일 하위업체·처리 국가·백업 소멸일을 임의로 기재하지 않았다. 이번 보완을 개인정보 관련 법적 의무 전체의 완료 인증으로 보아서는 안 된다.

1. Supabase 대시보드의 Authentication/Emails/SMTP 및 메일 훅에서 실제 발송 경로를 확인하고, 수탁업체·재위탁·국외 처리의 국가/항목/목적/기간/거부 방법과 적용 근거를 확정한다. 별도 동의가 필요하면 실제 이전 전에 안내/동의를 추가한다. 기본 메일 전송의 운영 한도와 비밀번호 재설정 수신도 별도 확인이 필요하다. 실제 메일을 시험 발송하지 않았다.
2. Supabase 무료 요금제의 제공사 복구/로그 정책과 별도로 만든 백업 유무를 확인한다. 유료 요금제 일일 백업의 7/14/30일 수치를 이 프로젝트의 실제 보관기간으로 단정하지 않는다. 앱 자체는 DB 백업을 생성하지 않는다. 복원 시에는 삭제된 계정을 재노출하지 않도록 삭제 요청을 재반영한다.
3. 운영자는 미승인/거절 계정 정리 기한을 확인하고 직접 삭제한다. 삭제 버튼을 구현했다고 30일 이내 정리가 자동 보장되는 것은 아니다. 정보 열람/정정/삭제/동의 철회 요청과 다른 회원이 포함된 사진의 동의 확인도 실제 운영 절차로 처리한다.
4. 운영자 계정과 서비스 관리 콘솔의 접근권한을 주기적으로 점검한다. Supabase 기존 유출 비밀번호 보호 경고는 프로젝트 요금제/보안 설정에서 검토한다.
