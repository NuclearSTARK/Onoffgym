# 배포 대기: 성별 기준 비교와 가입 승인 이력

2026-11-05 배포 지시로 이번 배포에 포함한다. 아래 배포 대기 표현은 구현 당시 기록이며, 최종 배포 기록은 [release-2026-11-05-gender-records-ui.md](release-2026-11-05-gender-records-ui.md)를 따른다.

2026-11-05 사용자가 합의된 수정사항 구현을 요청했다. 이번 수정은 로컬만 진행했으며 배포하지 않았다. 운영 Pages `e6024ffcbc0c`, main `7121fb9`, Edge API v29, Auth 이메일 자동 확인 설정과 실제 회원 데이터는 변경하지 않았다.

## 구현

- 신규 가입: 남자(`male`)·여자(`female`) 중 명시적 선택 필수. 선택 안 함·기본 추정값은 없다. 브라우저, 이메일 가입 어댑터, 현행 정책 버전의 Auth 가입 트리거가 검증한다. 가입 메타데이터의 역할은 권한으로 사용하지 않는다.
- 기존 회원·코치·운영자: 다음 로그인에서 성별 확인과 갱신된 개인정보 안내 동의를 한 번 완료한다. `privacy-2026-11-05`로 버전을 올리고 수집 항목·비교 목적을 안내한다. 나이 확인·선택 공개 동의는 기존 값이 유지된다. 동의 완료 후 다시 묻지 않으며, 개인정보 설정의 기존 동의 변경 화면에서 성별도 정정할 수 있다.
- 기존 계정의 성별은 nullable로 추가하고 추정·일괄 설정하지 않는다. 현행 가입 클라이언트는 성별 필수이며, 이전 클라이언트 가입은 대기 상태에서 정보 확인을 완료해야 승인된다.
- 1RM 및 NAMED WOD의 체육관 내 비교 집계를 같은 성별끼리 제한한다. 기존 종목 식별/별칭, 승인·공개 동의·순위 참여 조건, 회원별 최고 기록 1개, 동점, 시간/라운드 방향, 백분위·상중하 계산 및 비교 UI는 그대로 유지한다. 성별 미입력 계정에는 혼합 비교를 제공하지 않는다. 기존 기록을 다시 입력하거나 수정할 필요가 없다. 일일 수업 회원 기록 순위에는 성별 필터를 추가하지 않는다.
- 가입 최초 승인 시 기존 관리 이력에 `signup-approve`(가입 승인), 서버 시각, 검증된 작업자 ID와 작업 당시 이름을 저장한다. 대상 회원을 잠근 뒤 최초 승인 여부를 확인하여 중복 요청·동시 승인·재승인으로 새 가입 승인 행이 생기지 않는다. 승인 실패는 이력까지 함께 롤백된다.
- 관리 이력 화면에 승인자와 시각을 기존 변경 이력 형식으로 표시하며 기존 삭제 기능을 유지한다. 과거 이력은 만들어내지 않는다. 승인자를 알 수 없는 기존 계정은 `가입 승인자 정보 없음`으로 안내한다. 과거 `approved_at`은 가입일로 채워진 계정이 있어 이를 실제 승인 시각으로 표시하지 않는다.
- 이전 로컬 수정인 종목 카드별 1RM 계산기 팝업과 네비게이션 위치 보정을 보존한다. 상세: [pending-rm-calculator-2026-11-05.md](pending-rm-calculator-2026-11-05.md).

## 검증

- Node 자동 테스트 213개 통과.
- PostgreSQL 17 로컬 컨테이너에서 기존 전체 마이그레이션과 신규 마이그레이션 총 36개 재생 성공. Supabase의 Auth/Storage 최소 스키마와 실행되지 않는 cron 대체 함수만 사용했다. 외부 작업자·발송·원격 자격증명·실제 회원 데이터는 없다.
- SQL 검증: 남녀 집계 분리, 별칭·최고 기록·동점·시간/라운드 계산·공개/참여/승인 조건 유지, 기존 기록 보존 및 성별 정정에 따른 비교 집단 변경, 미입력/잘못된 값 거절, 구형 가입 클라이언트와 기존 승인 계정의 점진적 전환, 승인 권한·실제 작업자·이름 스냅샷·중복/재승인/동시 승인·실패 롤백, 직접 브라우저 DB/RPC 접근 차단.
- 운영 DB에서는 변경 대상 함수 6개의 소스 해시만 읽었다. 로컬 재생의 변경 전 함수 해시와 모두 일치했다. 운영 DB에 마이그레이션·데이터 변경을 적용하지 않았다.
- `qa-gender-approval.cjs` 통과: 가입 필수 선택, 세 역할 모두의 일회성 확인 및 재접속, 320/390/844px, 승인자 이름 HTML 이스케이프·시각·기존 이력 삭제 버튼. Auth/API 쓰기는 전부 모의 응답이다.
- `qa-rm-calculator.cjs`, `qa-nav-viewport.cjs`, `qa-unit-controls.cjs`, `qa-collected.cjs` 통과. 네비게이션은 화면 크기 값을 모의로 재현한 검증이며 실제 아이폰 검증은 하지 않았다.
- Worker, Pages, Edge API 빌드 성공. `git diff --check` 통과.

## 이후 배포 시

별도 배포 지시가 있을 때 신규 마이그레이션 `20261105101604_onoff_gender_comparisons_approval_history.sql`, API 번들, Pages 파일을 함께 배포해야 한다. main push는 자동 배포를 유발하므로 이번에는 하지 않았다. DB → API → Pages 순서와 로그인·기존 계정 정보 확인·신규 가입·운영자 승인 흐름을 확인한다. 실제 회원의 성별·동의·승인 값을 검증 목적으로 변경하거나 임의로 보충하지 않는다. 기존 Auth 이메일 자동 확인 설정은 유지한다.
