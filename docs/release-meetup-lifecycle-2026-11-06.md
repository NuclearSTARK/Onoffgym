# 운동 번개 마감·자동 정리

설정한 한국 시간의 번개 시작 시각을 기준으로 30분 뒤 마감한다. 커뮤니티 목록과 상세 화면의 본문·사진을 블러 처리하고 '마감'을 표시한다. 제목과 시간은 읽을 수 있다. 새 참여는 화면·API·DB에서 모두 차단하며, 이미 신청한 참여는 취소할 수 있다. 댓글은 보관 기한 전까지 유지한다.

상단 운동 번개 배너는 기존처럼 시작 30분 후 사라진다. 일반 공지는 유지한다. 목록·상세 화면을 열어둔 상태에서도 마감 시각에 갱신하고, 댓글을 쓰는 중이면 입력 내용을 유지한다. 시간 기준은 서버 시각으로 맞춘다.

보관 기한은 마감 이후가 아닌 시작 시각부터 24시간이다. 정확한 기한부터 앱 목록과 API 응답에서 제외하며, 서버의 매분 정리 작업이 게시글을 물리적으로 삭제한다. 기존 외래 키가 댓글·참여·사진 정보를 함께 삭제하고, 원본 및 미리보기 파일은 기존 비공개 Storage 정리함에 들어가 인증된 스케줄러의 API 삭제로 정리된다. 파일 삭제 실패는 다음 실행에서 재시도한다. 앱을 열지 않아도 진행된다. 다른 말머리와 시작 시각이 없는 기존 번개는 자동 삭제하지 않는다.

Supabase migration `20261106094547_onoff_meetup_lifecycle.sql`을 적용했다. Cron은 한 번에 최대 200개를 처리하고 잠긴 행은 다음 실행으로 넘긴다. 함수는 SECURITY INVOKER이며 anon·authenticated 실행 권한을 부여하지 않는다. 기존 스케줄러의 비밀 헤더 검증 후에만 Storage 정리가 실행된다. 지연된 번개 푸시는 30분 마감 후 발송하지 않는다. 신규 테스트 알림은 발송하지 않았다.

스와이프 추가 수정과 탭바 디자인은 변경하지 않았다.

## 검증

- 자동 테스트 226개, Pages·Worker·Supabase 번들 빌드 통과.
- `qa-meetup-lifecycle.cjs`: 모의 시계를 30분·24시간 경계로 이동해 목록/상세 블러, 마감 배지, 배너 종료·일반 공지 유지, 참여 취소 유지, 작성 중 댓글 보존, 24시간 목록 제거를 확인했다. 회원 API는 예시 응답만 사용했다.
- `supabase/meetup-lifecycle-tests.sql`: 실제 DB에서 마감 후 삽입 차단, 참여 취소, 만료 전 댓글 허용·만료 후 거부, 다른 말머리·시각 미등록 글 보존, 댓글·참여·사진의 연결 삭제와 원본/미리보기 정리함을 검증했다. 모든 검증 자료와 변경은 ROLLBACK했다.
- DB Cron의 실제 성공 실행과 비공개 함수 권한을 확인했다. Edge Function v31의 배포 소스가 검증한 번들과 일치하며 상태가 ACTIVE임을 확인했다. 상태 확인은 200, 비로그인 회원 API와 스케줄러 요청은 401을 확인한다.
- 보안 Advisor에 새 RLS/함수 경고는 없다. 기존 [유출 비밀번호 보호 비활성화](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 안내는 이 작업에서 변경하지 않았다.
