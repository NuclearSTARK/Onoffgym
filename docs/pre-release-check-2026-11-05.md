# 배포 전 버그·보안 확인

2026-11-05 작업본과 운영 프로젝트를 읽기 전용으로 점검했다. 운영 회원 자료, 권한, 암호, 알림 설정은 변경하지 않았고 메일·푸시도 발송하지 않았다. 아래 결과는 확인한 범위의 결과이며, 실제 휴대폰·TV 검사와 데이터 복구 시험을 대신하지 않는다.

## 확인한 결과

- 운영 DB의 앱 테이블 42개 모두 RLS 활성화. `anon`·`authenticated`의 직접 테이블 접근 권한과 공개 앱 RPC 실행 권한 없음.
- 사진 버킷은 비공개이며 JPEG만 허용. 서버에서 회원 승인 상태·공개 범위를 확인한 뒤 60초짜리 서명 URL을 제공한다.
- 운영 API에서 비로그인 회원 조회, TV 세션 없는 조회, 위조 토큰이 각각 401로 차단됨. 허용되지 않은 Origin은 403. 공개 키만으로 회원 테이블을 직접 조회하는 요청도 차단됨. 실제 회원 자료를 내려받는 검사는 하지 않음.
- 서버는 검증된 Auth 사용자와 DB의 현재 역할·승인 상태로 권한을 판단함. 사용자 수정 가능 metadata의 운영자 표시는 권한으로 사용하지 않음.
- 권한·사진·계정·인증·푸시·TV 관련 자동 테스트 85개 통과. 직전 전체 테스트 213개와 최근 TV 버튼·복귀·페이지 전환 검사도 통과.
- 이 점검 시점에는 TV 안내 수정이 작업본에 있었으며 실제 서비스에 배포하지 않았음. 후속 배포는 별도 배포 기록을 참고.

## 보완할 사항

1. **유출 비밀번호 차단 꺼짐 — 운영 보안 설정.** 운영 프로젝트 보안 Advisor의 경고 1개다. Supabase 공식 문서상 Pro 이상에서 제공하므로 요금제와 활성화 여부를 검토한다. 설정을 자동 변경하거나 유료 기능을 신청하지 않았다. [공식 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)
2. **로고 변환 도구 의존성 경고 — 개발 환경.** 전체 `npm audit`에서 중간 등급 5건, 높음·치명적 0건. `potrace → jimp → phin` 의존성에 걸린 경고로, 근본 항목은 `phin`의 리다이렉트 시 민감 헤더 전달 가능성이다. 현재 해당 도구는 로컬 로고 이미지 변환 스크립트에서만 쓰며 앱의 회원 요청에는 포함하지 않는다. 개발 도구 정리·대체·호환성 확인 후 갱신할 항목이다. `npm audit --omit=dev`는 0건이지만 이것만으로 브라우저에 별도 보관한 모든 파일의 안전성을 인증하지는 않는다. [경고 원문](https://github.com/advisories/GHSA-x565-32qp-m3vf)
3. **회원권 미등록 접근 — 운영 정책 확인.** 현재 `membershipState(null, ...)`는 `active: true`다. 가입 승인 후 회원권이 아직 없어도 기본 접근을 허용하는 기존 정책이다. 회원권 등록 전 이용을 차단하려는 운영 방침이면 별도 변경이 필요하다. 코치·운영자의 카드 표시 설정과는 다른 항목이다.

## 운영자가 실제로 확인할 순서

1. **일반 회원·코치·운영자 계정:** 일반 회원에게 운영 메뉴·관리 메모가 보이지 않는지, 코치에게 부여한 기능만 보이는지 확인한다. 공개 동의를 끈 계정의 기록·사진이 다른 회원에게 보이지 않는지도 확인한다.
2. **비밀번호 복구:** 본인 이메일로 재설정 메일을 받아 링크를 열고 새 비밀번호로 로그인한다. 메일 수신·스팸함·복귀 주소와 발송 한도는 모의 시험만으로 확인되지 않는다.
3. **회원권·출석:** 만료·휴회·잔여 1회 상태와 같은 날 재출석을 확인한다. 두 기기에서 눌러도 중복 차감되지 않아야 한다.
4. **아이폰·안드로이드:** 홈 화면에 추가한 앱에서 로그인하고 잠금 화면 푸시 수신을 확인한다. 탭 이동·가로 회전·키보드 사용 시 내비게이션과 팝업이 화면을 가리지 않는지도 확인한다.
5. **75인치 TV:** 설정 → 앱 등록 → QR 스캔 → 홈 화면 추가를 직접 진행한다. 안내의 돌아가기 버튼·Esc와 운동 자동 넘김, 장시간 표시·네트워크 복구·공개 시각의 날짜 전환도 확인한다.
6. **백업·복구:** 운영 DB와 비공개 사진 파일의 백업 유무, 보관 위치·접근 권한·복원 담당자를 확인한다. 코드 ZIP만으로 회원 자료가 백업되지는 않는다. 실제 복원 시험은 별도 테스트 환경에서 진행하며 이번 점검에서는 수행하지 않았다.

개인정보 문의처·처리방침의 실제 운영 내용과 GitHub·Supabase 관리 계정의 2단계 인증도 운영자가 확인한다. 가입 이메일 인증은 현재 운영 정책대로 생략되어 있으므로, 승인 시 체육관 회원의 실명과 실제 사용하는 이메일인지 확인한다.
