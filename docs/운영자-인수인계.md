# 온오프 앱 운영자 인수인계

## 이번 단계

GitHub에 소스를 보관하고 검사를 자동 실행합니다. Supabase 연결·데이터 이전은 요청에 따라 보류했습니다. GitHub에 소스를 올리는 작업과 실제 서비스 호스팅은 별개입니다. GitHub Actions는 테스트와 배포 파일 생성만 수행하며, 운영 사이트를 자동 배포하거나 회원에게 알림을 보내지 않습니다.

## 현재 서비스

- 미리보기: https://onoff-crossfit-gym.powerloding.chatgpt.site
- 로그인 첫 화면: https://onoff-crossfit-gym.powerloding.chatgpt.site/#login
- 현재 사이트는 소유자 전용 비공개입니다. GitHub 초대만으로 앱 접속 권한이 생기지 않습니다.
- 출석은 버튼 한 번으로 서버에 저장합니다. 위치를 수집하지 않습니다. 한국 날짜 기준 하루 한 번이며 중복 클릭해도 한 건입니다.
- 카카오 로그인 화면은 준비되었지만 실제 카카오 인증은 연결 전입니다.

## 데이터 보관 현황

현재 D1 서버에 수업, 공개 시각, 회원 승인·권한, 동작 영상, 운영자 공지, 출석, 웹 푸시 구독을 저장합니다. 운동 결과·1RM·일반 게시판 등은 아직 브라우저 미리보기입니다. 실제 회원 운영 전에는 해당 데이터를 Supabase 등 공용 저장소로 연결해야 합니다. 브라우저 기록이나 개인 데이터를 GitHub에 올리지 않습니다.

## GitHub 소유권과 앱 운영자 권한

1. 소스 저장소는 Private를 유지합니다.
2. 코드 접근 권한은 GitHub 저장소 Settings → Collaborators에서 운영자의 GitHub ID로 초대합니다.
3. 앱 접속은 사이트 공유 설정에서 별도로 허용해야 합니다.
4. 접속한 운영자 계정을 앱의 운영 → 회원 승인·권한 관리에서 운영자로 지정합니다.
5. 서비스 소유권까지 넘길 때는 저장소 이전, 호스팅 계정, DB 소유권과 런타임 설정을 함께 이전합니다. 비밀번호를 공유하지 않습니다.

## 개발·검사

Node.js 24 권장. 외부 npm 의존성 없이 다음 명령을 사용할 수 있습니다.

```sh
npm test
npm run build
node scripts/dev.mjs
```

`dev.mjs`는 메모리 DB와 가짜 로그인 쿠키를 사용하는 로컬 전용 어댑터입니다. 배포 파일에 포함되지 않습니다. 워크북 재생성은 Python openpyxl이 필요합니다.

## 로그인과 외부 호스팅

현재 Worker는 Sites가 검증해 주는 인증 헤더를 신뢰합니다. 이 Worker를 인증 변경 없이 공개 Cloudflare/Vercel 등의 주소에 배포하면 안 됩니다. 외부 호스팅으로 이전할 때는 Supabase Auth의 토큰을 서버에서 검증하도록 교체한 다음 공개합니다. 카카오 로그인, 승인 대기, 역할 검사도 해당 인증 ID를 사용해야 합니다.

## 웹 푸시

- 회원은 내 정보 → 웹 푸시 알림에서 이 기기의 구독을 켜거나 끕니다.
- 운영자는 공지 작성·수정 시 ‘푸시 보내기’를 직접 선택할 수 있습니다.
- 시험 알림은 요청한 계정의 구독 기기에만 보냅니다.
- 아이폰은 지원되는 iOS에서 Safari의 ‘홈 화면에 추가’ 후 앱을 열고 알림을 허용해야 합니다.
- 서비스 워커는 회원 페이지나 데이터를 캐시하지 않고 알림만 처리합니다.
- 예약 실행이 아직 연결되지 않았으므로 운동 공개 자동 푸시는 활성화되지 않았습니다. 앱 화면에서도 연결 전으로 표시합니다. `scheduled` Worker 핸들러와 큐는 준비되어 있습니다.
- 외부 호스팅과 인증 이전 후 매분 예약 실행을 연결하고 `dispatchReleasePush`를 호출하면 최근 10분 내 공개된 운동에 대한 알림을 중복 없이 처리합니다. 소규모 배치로 구독자에게 순차 전달하며 재실행이 필요합니다. 예약 연결 및 실제 수신을 검증한 뒤에만 `PUSH_SCHEDULER_CONFIGURED=true`로 설정합니다.

런타임 설정: `ONOFF_OWNER_EMAIL`, `VAPID_PRIVATE_JWK`(비밀), `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`, `PUSH_SCHEDULER_CONFIGURED`. 실제 키는 소스에 없으며 호스팅 환경에만 저장합니다. 키와 서비스 주소가 변경되면 기기의 재구독이 필요할 수 있습니다.

## 운영 전 남은 연결

카카오 인증, 회원 전체의 공용 운동 기록·1RM·일반 게시판, 운영자 접속 초대, 외부 호스팅 소유권, 자동 알림 예약 실행 및 실제 휴대폰 수신을 확인해야 합니다. 이번 단계에서는 Supabase를 생성하거나 이전하지 않았습니다.

## 공개 GitHub Pages 테스트

GitHub Pages의 공개 테스트 버전은 실제 서버와 분리되어 있습니다. 주소는 배포 성공 후 `https://nuclearstark.github.io/Onoffgym/`입니다. 운영자 화면을 누구나 체험할 수 있지만 예시 데이터만 사용하고 입력은 각 브라우저에 저장됩니다. 로그인·역할·출석·회원 승인·공지·운동 기록은 이 공개 버전에서 실제 회원 서비스로 작동하지 않습니다. 실제 카카오 인증이나 푸시 발송도 연결하지 않습니다. 상단 테스트 안내를 유지합니다.

개인 정보나 실제 회원 정보를 입력하지 말고, 회원 운영은 서버·인증 연결과 별도로 준비합니다. 기존 Sites의 회원 서버 접근 범위는 이 공개 테스트와 무관하게 유지됩니다. 배포는 `.github/workflows/pages.yml`에서 수행하며 저장소 Settings → Pages → Source가 GitHub Actions여야 합니다.
