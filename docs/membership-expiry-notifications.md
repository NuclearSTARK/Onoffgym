# 회원권 만료 3일 전 자동 알림

한국시간 매일 오전 9시부터, 현재 회원권 만료일이 3일 뒤인 승인 회원의 알림 허용 기기에 보냅니다. 기존 매분 예약 발송기를 사용하므로 앱을 열어두지 않아도 발송됩니다. 예약 처리·기기 상태에 따라 수신 시각이 늦어질 수 있습니다.

- 시작일이 지났고 휴회 중이 아닌 기간권 및 만료일이 있는 횟수권이 대상입니다.
- 만료일 없는 횟수권, 잔여 횟수 0, 가입 대기·이용 중지·삭제 처리 중 회원은 제외합니다.
- 기존 알림 구독도 기본 포함합니다. 개인설정 → 알림 설정 → 회원권 만료 알림에서 이 항목만 끌 수 있습니다. 전체 알림을 껐거나 만료된 구독에는 발송하지 않습니다.
- 한 회원권의 같은 종료일에는 하나의 알림 작업만 만들고, 수신 허용된 기기별로 한 번 처리합니다. 연장하면 새 종료일을 기준으로 다시 예약합니다.
- 작업 생성, 수신 기기 선택, 실제 전송 직전에 조건을 확인합니다. 예약 후 연장·삭제·휴회·알림 해제·회원 상태 변경이 있으면 이전 알림을 보내지 않습니다.
- 알림을 누르면 로그인한 본인의 최신 회원권을 엽니다. 회원카드를 평소 숨겨둔 운영자·코치에게도 본인 카드만 표시합니다.
- 운영 → 푸시 알림 보내기 → 최근 발송 이력에서 발송 결과를 확인할 수 있습니다.

문구:
> 회원권 만료 3일 전
> 회원권이 YYYY-MM-DD에 만료돼요. 이용 기간을 확인해주세요.

OpenAI API를 사용하지 않습니다. 기존 푸시 예약·암호화·전송 경로를 사용합니다.

## 최초 적용

DB migration: `20261111033617_onoff_membership_expiry_push.sql`. 첫 예약 기준 시각은 **2026-11-12 09:00 (한국시간)**입니다.

DB의 `membershipExpiryPushStartAt`에 배포 이후 첫 오전 9시(KST)를 저장합니다. 배포 당일 이미 지난 9시 알림은 소급 발송하지 않습니다. 당일 예약기 장애가 있다면 같은 한국 날짜 안에서 지연 처리하며 다음 날 과거 알림을 보내지 않습니다. 현재 공지·운동 공개·가입 승인 요청 알림 동작과 예약기는 유지합니다.

## 검증

`npm test`, `npm run build:backend`, `npm run build:cloudflare`, `npm run build`.
격리된 PostgreSQL/PGlite에서 실제 migration과 `supabase/membership-expiry-push-tests.sql`을 실행하여 9시 경계·날짜·개인별 수신·중복·연장·휴회·잔여횟수·권한을 검증합니다.
`python tests/browser/membership-reminder.py`는 가짜 로그인/API/구독으로 알림 설정과 본인 회원권 연결을 검증합니다. 실제 회원에게 시험 알림을 보내지 않습니다.
