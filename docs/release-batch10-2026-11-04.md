# ONOFF 모바일 정렬·사진 로딩 개선

기존 batch9 수정은 유지한다. 네비게이션의 기기 안전영역을 제외한 높이는 58.1px에서 52.3px로 10% 줄이고 배경 불투명도는 80%를 유지한다.

## 화면 변경

- 출석 달력은 같은 높이의 날짜 칸 위에 30종의 이모지를 도장처럼 겹쳐 표시한다. 회원·날짜별 결정적 해시로 다양하게 배정하므로 다시 열어도 바뀌지 않는다. 출석 날짜의 큰 배경색은 없애고 오늘은 작은 원으로 표시한다.
- 앱 설정 네 줄은 높이/여백/오른쪽 컨트롤을 맞추고 중량 단위를 작은 선택 버튼으로 묶는다.
- 적립 항목의 `적립 방식` 라벨을 다른 필드와 같은 크기로 맞추고 우측에 작은 테두리 `관리` 버튼을 둔다. 포인트 설정에서 요청한 출석/개인 기록 적립 안내 문단을 제거한다.
- 회원 목록은 64px 높이 한 줄에 이모지·이름·권한·만료일·상세 버튼을 배치한다. 기간/횟수권 종류 설명을 빼고 날짜는 YYYY.MM.DD, 없으면 —로 표시한다. 10명 단위 스와이프, 상태/권한 필터, 메모 검색과 상세 내용은 유지한다. 권한 버튼은 같은 크기로 맞추며 승인 완료 상태를 작게 표시하고 기한 초과가 0명이면 수치를 숨긴다.
- 회원 상세의 보유 포인트는 큰 값의 숫자와 P가 잘리지 않게 행 높이/줄간격/넘침을 조정한다.
- 회원 기록 화면 날짜 선택을 본문 전체 너비로 넓혀 320px에서도 날짜를 읽을 수 있게 한다.
- 타이머 스피커 옆 스위치를 없애고 스피커 버튼에 0~100% 슬라이더를 연결한다. 계정별 마지막 음량을 저장하며 비프와 GO 음성 모두 같은 값을 따른다. 0%는 음소거다. 조절 중 타이머/입력을 다시 만들지 않는다.
- 타임테이블의 B/T는 파랑, WOD는 주황, OPEN GYM은 회색을 시간/종목/윗선에 적용하고 선택 배경도 해당 색으로 맞춘다.

## 사진 변경과 권한

기존은 서명 URL을 받고 `fetch().blob()` 다운로드가 끝난 뒤에야 이미지 요소에 넣었고, 미리보기와 확대가 같은 최대 1600px 파일을 사용했다. 시간 제한이 없는 대기 Promise가 화면 재진입 후에도 남을 수 있었다.

- 새 업로드는 원본(긴 변 최대 1600px, 최대 600KB)과 목록용 480px JPEG(목표 48KB, 최대 64KB)를 함께 저장한다. 두 개가 모두 저장돼야 첨부 가능한 상태로 바뀐다. 최대 두 장을 병렬 업로드하며 부분 성공은 재시도 시 재사용한다.
- 목록은 작은 파일의 서명 URL을 브라우저 이미지 요소에 바로 할당한다. 확대는 별도로 원본을 요청한다. 브라우저 다운로드 후 캐시에 저장하는 작업은 표시를 막지 않는다.
- 같은 서명 URL을 사용한 이미지 표시와 백그라운드 저장 사이 HTTP 캐시가 재사용되는지 확인했다. 가까운 사진 두 개만 서명 URL을 미리 준비한다.
- 8초 서명 요청 제한과 한 번의 제한된 재시도, 이미지 로드 12초 제한, 실패 후 명시적인 다시 시도 버튼을 추가했다. 실패한 Promise는 항상 해제한다. 확대 화면에도 다시 시도가 있다.
- 메모리 캐시는 최대 48개, 계정별 CacheStorage는 최대 60개/24시간이며 JPEG만 저장한다. 앱 시작 시 계정이 아직 결정되지 않은 동안 삭제하지 않고, 확인된 로그아웃/계정 전환 때 삭제를 직렬화한다. 로그아웃/탈퇴는 디스크 삭제 완료를 기다린다.
- 저장된 바이트는 현재 승인된 계정의 bootstrap 또는 새 서명 API가 해당 사진을 허용한 뒤에만 읽는다. 허용 상태는 55초로 제한하며 이후에는 서버 권한을 다시 확인한다. 서명 URL은 바이트 캐시와 분리해 만료를 연장하지 않는다.
- 기존 6장 모두를 사전에 변환했다는 의미는 아니다. 기존 사진은 원본을 바로 표시하고, 소유자나 운영자가 열 때 작은 미리보기를 비동기로 준비한다. 다른 회원은 다른 소유자의 미리보기를 생성할 수 없다. 이후에는 작은 파일을 사용한다.
- `preview_path`만 추가하고 private bucket/서버 전용 RLS/공개 동의 검사를 유지한다. 호출자가 저장 경로·소유자를 선택할 수 없다. 삭제/탈퇴는 원본과 미리보기를 모두 정리하며 업로드·삭제 동시 실행도 정리 큐로 처리한다.

## 검증

- Node 테스트 182개 통과: 기존 회귀와 새 미리보기 저장/실패, 접근 권한, 개인정보 비노출, 삭제, 디스크 캐시 계정 분리/수량/기간/경합, 멈춘 요청, 도장 다양성 포함.
- Playwright Chromium: batch10 320/390/844px에서 정렬/잘림/안전영역/음량 저장 확인. batch9/8/6 회귀 확인. 별도 타이머 테스트로 비프 gain과 GO 음성이 35%를 따르고 0%에서 종료음이 없으며 계정별 음량이 분리됨을 확인했다.
- DB 변경과 원본/미리보기 삭제 트리거 검증은 BEGIN/ROLLBACK으로 진행했다. 실제 회원/포인트/동의/글 삭제나 푸시 발송은 하지 않았다.
- `npm run build`, `build:backend`, `build:pages` 통과. Edge v25, `verify_jwt=false` 유지 + 함수 내부 Bearer 검증 유지. 메일 즉시 가입 설정 유지. 보안 advisor는 기존 유출 비밀번호 보호 비활성 경고만 유지되며 새 RLS 경고는 없다.

### 제어된 사진 비교

`qa-photo-performance.cjs`는 batch9의 실제 photos.js와 새 코드를 같은 로컬 HTTP 서버/Chromium에서 비교한다. 서명 지연 100ms, 이미지당 초당 163,840바이트, 사진 두 장(원본 각각 276,214바이트/1280px, 미리보기 26,569바이트/480px)의 모든 이미지 디코딩 완료 시점을 측정했다. 실제 아이폰/안드로이드 또는 LTE 속도 측정은 아니다.

| 조건 | 기존 | 개선 |
|---|---:|---:|
| 처음 열기 | 2,216ms | 538ms |
| 같은 화면 재진입 | 22ms / 재다운로드 0 | 9ms / 재다운로드 0 |
| 새로고침 후 열기 | 1,902ms / 552,428바이트 | 37ms / 재다운로드 0 |
| 처음 전송량 | 552,428바이트 | 53,138바이트 |

첫 표시 약 76%, 최초 전송량 약 90% 감소를 이 조건에서 확인했다. 캐시 저장 때문에 같은 파일을 추가 다운로드하지 않았다. 16초 내 멈춘 서명 요청 해제, 이후 재요청 성공, 실제 이미지 오류 후 재시도, 확대 원본 해상도 유지, bootstrap에 없는 디스크 사진의 서버 재허가도 검증했다. 환경과 사진 복잡도에 따라 시간은 달라진다.
