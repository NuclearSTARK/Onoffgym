# ONOFF 버그·보안 점검 — 2026-11-18

## 적용 상태와 비용

수정은 작업본에 완료했다. GitHub push, Cloudflare 배포, 운영 Edge 교체, 운영 DB 마이그레이션 적용은 하지 않았다. 운영 DB 검증은 가상 계정·자료를 넣는 하나의 트랜잭션에서 실행하고 모두 ROLLBACK했다. 원래 함수가 복원된 것도 별도로 확인했다. 실제 회원의 기록·권한은 변경하지 않았고 메일·푸시는 발송하지 않았다.

새 유료 서비스, R2, OpenAI API, 유료 요금제, 결제를 활성화하지 않았다. 이번 수정에는 별도 구독이 필요 없다. 기존 계정의 청구·구독 전체를 조회한 것은 아니므로 앞으로 모든 청구가 0원이라고 보장하는 점검은 아니다. 무료 한도 초과 시 유료 업그레이드를 자동으로 진행하지 않는다.

## 운영 환경에서 확인한 방어

- 앱 테이블 47개 모두 RLS 활성화. `anon`, `authenticated`에는 직접 조회·쓰기 권한이 없다.
- 공개 앱 RPC의 클라이언트 실행 권한과 관리용 뷰·함수의 권한을 확인했다. 권한은 사용자가 수정할 수 있는 metadata가 아니라 검증된 Auth 사용자와 DB의 현재 역할·승인 상태로 판단한다.
- 사진 버킷은 비공개이고 JPEG·파일 크기 제한이 있다. URL 발급은 승인·공개 범위를 검사하며 유효기간은 60초다.
- 실제 운영 API에서 비로그인 회원 조회, 위조 토큰, 비로그인 권한 변경, TV 세션 없는 조회, 테이블 직접 조회, 관리 RPC 직접 호출이 401로 거절됐다. 허용하지 않은 Origin은 403이었다. 테이블 검사는 `limit=0`으로 회원 행을 받지 않았다.
- 푸시 구독 목적지의 HTTPS·허용 호스트 검사와 리다이렉트 거절을 확인했다. TV 인증은 시도 횟수를 제한하며 임의의 회원 신원으로 바뀌지 않는다.
- 현재 소스·비무시 파일 382개의 비밀키 패턴 검사에서 해당 패턴의 노출을 찾지 못했다. 공개 publishable key는 비밀키가 아니다. 전체 Git 이력을 전수 검사한 결과는 아니다.
- 보안 Advisor의 미사용 사진 AI 테이블 4개 안내는 RLS와 접근 차단이 된 상태다. 경고를 없애려고 공개 정책을 추가하지 않았다.

## 무료로 할 보안 보완

1. **관리 계정부터 2단계 인증:** Cloudflare, GitHub, Supabase와 가입 이메일 계정에 무료 인증 앱 또는 기기 패스키를 사용한다. Cloudflare는 이메일 추가 인증도 지원한다. 계정 화면은 [My Profile → Authentication](https://dash.cloudflare.com/profile/authentication)에서 확인한다. 이번 작업에서 계정 설정을 직접 바꾸지는 않았다. [Cloudflare 공식 안내](https://developers.cloudflare.com/fundamentals/user-profiles/2fa/), [이메일 인증 안내](https://developers.cloudflare.com/fundamentals/user-profiles/multi-factor-email-authentication/)
2. **비밀번호 재사용 방지:** 관리자마다 다른 긴 비밀번호를 사용한다. Supabase의 유출 비밀번호 차단은 공식 문서상 Pro 이상이므로 활성화하지 않았다. 긴 비밀번호와 2단계 인증은 무료 보완책이지만 유출 비밀번호 목록 검사와 동일한 기능은 아니다. [Supabase 비밀번호 보안](https://supabase.com/docs/guides/auth/password-security)
3. **봇 방어가 필요하면 Turnstile Free:** 가입·복구 요청 남용을 줄일 수 있다. 무료 플랜을 명시해 사용하고, Supabase Auth 서버에서 토큰을 검증하도록 연결해야 한다. 화면에만 붙이면 직접 Auth 호출로 우회된다. 계정별 site key/secret과 로그인·복구 흐름 변경이 필요해 이번 수정에 임의로 켜지 않았다. CSP의 허용 스크립트 출처도 함께 조정해야 한다. [무료 플랜](https://developers.cloudflare.com/turnstile/plans/)
4. **무료 로컬 백업:** DB와 비공개 사진을 운영자 PC의 암호화된 저장소에 주기적으로 별도 보관한다. GitHub 코드만으로 회원 데이터가 복구되지는 않는다. 유료 백업·스토리지를 신청하지 않았고 실제 복원 시험도 수행하지 않았다.
5. **계정 사고 시 세션 처리:** 짧은 JWT 만료 시간을 검토하고, 즉시 차단이 필요한 경우 DB의 승인 상태도 함께 중지한다. Supabase의 기존 액세스 토큰은 로그아웃 후에도 만료 전까지 유효할 수 있다. 엄격한 즉시 해제는 검증된 `session_id`의 존재를 서버에서 확인하는 별도 설계가 필요하다. 이를 위해 민감한 Auth 테이블 전체를 무작정 공개하거나 서버 권한을 넓히지 않았다. [공식 세션 안내](https://supabase.com/docs/guides/auth/sessions)

웹 GPS 좌표는 조작될 수 있어 완전한 부정 출석 방지 수단은 아니다. 현재의 서버 거리 검사와 운영자 예외 출석을 유지한다. 자동 출석, 도장 확대, OCR·AI 도입은 이번 수정에 포함하지 않았다. 회원권 미등록 회원의 기본 접근 허용도 기존 운영 정책을 유지한다.

## 운영 반영 순서

후속 운영 반영 시 `20261118113052_onoff_atomic_write_permissions.sql` → 새 `onoff-api` 번들 → 정적 화면 순으로 적용한다. Edge의 `verify_jwt=false`는 핸들러 내부 `auth.getUser(token)` 검증을 사용하는 현재 구성과 함께 유지하고 `deno.json` import map을 포함한다. GitHub main push는 자동 배포를 시작할 수 있으므로 이 작업에서는 push하지 않았다.

DB 시험은 다음 조합으로 다시 실행할 수 있다: `BEGIN;` + 후보 마이그레이션 + `supabase/security-write-tests.sql`의 중복 `BEGIN;`을 뺀 본문. 끝의 `ROLLBACK;`을 유지한다. 해당 파일의 임시 권한 검사 함수는 오래된 선행 검사 상황을 모의하기 위한 것이므로 운영 마이그레이션에 포함하면 안 된다.
