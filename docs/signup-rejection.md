# 승인 거절·이용 중지 분리

운영 회원 관리에 `승인 거절` 분류를 추가했다. 승인 이력이 없는 거절 계정과, 이미 승인됐던 회원의 이용 중지를 구분한다. 기존 `approved_at`을 기준으로 기존 계정도 분류하며 상태나 과거 사유를 임의로 다시 쓰지 않는다. 계정 삭제 처리 중인 회원은 재신청 대상이 아니다.

회원 정보의 계정 상태에서 `승인 거절`을 선택하면 사유 입력란이 열린다. 사유는 선택 입력이고 최대 500자이며, 비워두면 카운터 문의를 안내하는 기본 문구를 사용한다. 회원의 로그인 화면에는 거절 안내와 해당 사유를 표시한다. 관리자 이력에는 거절한 운영자 이름·시각·사유가 남는다. 일반 회원에게 다른 사람의 거절 사유를 공개하지 않는다.

거절된 회원은 같은 이메일·계정으로 로그인해 실명을 정정하고 `다시 승인 요청`할 수 있다. 계정 ID와 역할은 유지하며 승인 대기로 전환하고 재신청 이력과 운영자 알림 작업을 만든다. 중복 요청은 새 이력·알림을 추가하지 않는다. 기존 승인 회원의 이용 중지와 삭제 처리 중인 계정은 이 경로로 풀 수 없다. 재신청으로 개인정보 보관기한이 계속 연장되지 않도록 기존 거절 시각을 보존하고, 승인 시 거절 사유·시각을 정리한다. 과거 이력은 유지한다.

## 검증

- 단위/API 테스트 234개 통과. 다른 회원 ID·역할을 제출해도 로그인한 본인만 재신청한다.
- `supabase/signup-approval-tests.sql`을 격리한 로컬 PostgreSQL(PGlite)에서 실행했다. 기존 운영 DB 함수 정의는 읽기만 하여 테스트에 사용했다. 거절·재신청·다시 승인·기본 사유·중복 방지·권한·보관기한을 검증하고 모든 테스트 데이터를 롤백했다.
- 새 함수 두 개는 `SECURITY INVOKER`이며 PUBLIC·anon·authenticated 실행을 차단하고 service_role만 허용한다. 기존 테이블의 RLS와 브라우저 직접 접근 제한을 유지한다.
- Chromium 휴대폰 크기에서 거절/이용 중지 목록 분리, 사유 입력·저장, 회원에게 특수문자와 줄바꿈 표시, 재신청 후 대기 화면, 이용 중지 계정의 재신청 버튼 미노출을 검증했다. 모의 API만 사용했으며 실제 회원 정보나 알림은 변경하지 않았다.
- Edge API 번들, Cloudflare Pages 및 기존 Worker 빌드 통과.

## 운영 적용

2026-11-10 운영 DB에 `20261110124202_onoff_signup_rejection_reapply.sql`을 적용하고 Edge API v33을 배포했다. 새 함수의 브라우저 직접 실행 차단, 서버 실행 권한과 기존 RLS 유지 여부를 확인했다. 실제 회원의 승인 상태를 시험으로 변경하거나 테스트 알림을 발송하지 않았다.

화면은 GitHub main과 연결한 Cloudflare Pages 자동 배포를 사용한다. 기존 회원에게는 로그인 방식·이메일 변경이나 재가입이 필요하지 않다. 적용 순서는 DB 마이그레이션 → Edge API → 프런트엔드다.
