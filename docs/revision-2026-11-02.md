# 2026-11-02 회원 앱 개정

실제 서비스: https://nuclearstark.github.io/Onoffgym/ (GitHub Pages + Supabase).
이 변경은 실제 회원 삭제, 시험 출석 삭제, 이메일 확인 설정, 자동 승인, TV 암호 변경을 수행하지 않는다.

## 권한

기존 `coach` boolean은 계속 운영자만 뜻한다. 실제 코치 역할은 `viewer.role === 'coach'`와 DB의 `coach_permissions`로 구분한다. `web/permissions.js`가 허용 목록이며 기본은 빈 배열이다. 프런트 `can()`은 표시용이고, Edge의 검증된 Auth UUID에 연결된 회원 행 및 서비스 전용 DB 함수가 변경 권한을 다시 확인한다. `user_metadata`는 판단에 쓰지 않는다.

회원관리·가입 승인·회원권·구분 메모·역할 및 코치 권한·저장공간은 운영자 전용이다. 코치 기록 입력용 명단은 `recordMembers`의 id/name/status뿐이며, 회원관리의 `members`, 회원권, 변경 이력, 전체 출석은 제공하지 않는다. 미공개 수업 조회·생성·수정·삭제 및 회원 기록 생성·수정·삭제는 별도 권한이다. 수업 편집 시 미공개 원문도 확인하려면 조회 권한을 함께 부여한다. TV 권한은 화면 설정만 허용하며 인증 암호 변경과 연결 일괄 해제는 운영자만 가능하다.

## 사진

커뮤니티는 일반 글에 최대 3장, 오늘의 기록은 날짜/B/T·WOD/수업 시각별 최대 3장이다. 오늘의 기록은 운동/회원 기록 등록 없이도 사진만 올릴 수 있다. 회원 기록·일괄 입력·S1/S2·1RM은 함께 유지한다.

클라이언트는 원본을 업로드하지 않는다. 캔버스로 JPEG를 만들고 긴 변 1600px, 400KB 이하를 목표로 압축하며 품질·해상도를 낮춰 재시도한다. 최종 상한은 600KB, 원본 입력은 25MB/60MP다. 브라우저가 HEIC 등을 해독하지 못하면 JPG/PNG 변환 안내를 제공한다. 서버도 JPEG APP/COM 메타데이터를 제거해 위치정보를 보관하지 않는다.

`onoff-private-photos`는 비공개이며 직접 브라우저 테이블/저장소 접근 권한이 없다. DB는 경로·첨부 관계를, Storage는 압축 파일을 보관한다. 승인된 사용자에게만 60초 서명 URL을 발급한다. 파일 업로드가 먼저 성공한 항목은 재시도 때 다시 올리지 않는다. 첨부 확정은 DB 트랜잭션이며 일일 사진의 동일 첨부 재시도도 멱등이다.

글 삭제는 사진 행을 삭제하고 파일 경로를 영속 정리 큐에 넣는다. API가 파일을 지우고 성공한 큐 항목만 제거한다. 실패하면 다음 인증 요청에서 다시 처리한다. 미사용 업로드는 24시간 경과 후 다음 bootstrap/업로드 시 최대 30개씩 정리한다. 별도 유료 작업자나 AI 인식은 사용하지 않는다.

## 화면

- 홈 제목 아래에 선택/진행 중/다가오는 수업·휴강 상태를 표시하고 중복 안내를 제거했다. 날짜/출석 가로 폭과 운동 본문의 크기·굵기를 키웠다.
- 공지의 hover/focus 정지 규칙을 해제하고 동일한 두 사본을 정확히 반 길이만큼 반복한다. 필요한 DOM 교체 시 애니메이션 시간을 이어간다. 관찰 가능한 정지/재생 조건을 수정했으며 모든 기기의 원인을 하나로 단정하지 않는다.
- 회원 기록은 같은 회원의 S1→S2를 한 행 안에 묶고, 첫 선택은 B/T이며 공개 안내를 중앙 정렬한다.
- 구간 제목은 새 편집 UI와 홈·TV에서 숨긴다. 이전 제목은 숨은 필드에 보존하고 빈 새 제목은 서버 검증용 S번호로 정규화한다. 기존 데이터 일괄 삭제는 없다.
- 구간 탭/가로 제스처로 한 구간씩 편집하며 텍스트 입력/선택 영역은 제스처 대상에서 제외한다. 초안·추가·제거·숨은 구간의 필수 입력 검증을 유지한다.
- 쉼표/세미콜론/줄바꿈 뒤 동작 검색도 같은 추천 목록을 쓰며, 키보드 공간을 고려해 입력과 내부 스크롤 목록을 함께 보이게 한다.
- 텍스트/여러 줄/검색/숫자/이메일/비밀번호/URL/전화 입력은 값이 있으면 테두리 없는 X를 제공한다. input/change를 발생시켜 폼·초안·자동완성에 반영하고 포커스를 유지한다.
- TV 연결 목록은 이름/연결 상태만 남기고 가로 화면의 수업 박스와 글자를 키웠다.
- 등록 일정은 날짜별 묶음, 오늘 이후/지난 수업, 날짜 검색, 5일 단위 페이지다.
- 푸시 이력은 한 줄 메시지/시각/발송 결과이고 펼치면 전체 메시지·수량·저장된 실패 사유가 나온다. 기존 이력에 사유가 없으면 없다고 표시한다. 발송은 단말 수신 확인을 뜻하지 않는다.
- 1RM/계산기의 그림·여백을 줄이고, 기본/선택 배지는 파랑/회색과 글자를 함께 쓴다.

## 저장공간

2026-11-02 공식 문서와 조직 정보에서 Free를 확인했다. DB 500MB/프로젝트, 파일 1GB/조직, 월 비캐시·캐시 전송 각 5GB다. DB는 `pg_database_size`, 파일은 Storage 객체 메타데이터 크기 합계를 사용한다. 화면은 운영자에게만 보이며 2분마다 갱신하고 80%부터 주의 색상이다. 관리 비밀키는 클라이언트에 없고, 전송량의 실제 청구 계량은 앱에서 얻지 못하므로 조회 불가와 Supabase Usage 링크를 표시한다.

## 검증 및 제한

Node 자동 테스트 102개와 Pages/Worker/Edge 빌드를 확인했다. 브라우저는 320/390/844/1440px 편집·탭·X·자동완성, 모의 인증을 사용한 회원별 기록 묶음, 사진 압축·2장 중 실패·성공분 재사용·글 대표/상세/확대·오늘의 기록 사진만 저장, 코치 메뉴/TV 인증 UI 제한을 확인했다. `qa-revision.cjs`는 Playwright를 설치한 환경에서 5173 포트로 Pages를 제공하면 실행 가능하며 모든 API를 가로채 실제 푸시/이메일/회원 데이터를 사용하지 않는다.

운영 DB는 가짜 UUID/예시 주소의 격리 행을 트랜잭션 안에서 만들고 모두 롤백하여 권한 거부·허용, 첨부 확정·재시도, 글 삭제 정리 큐를 검증했다. 실제 회원으로 로그인하거나 실제 사진/푸시를 전송한 검증과는 구분한다. 390×360 키보드 축소 모의 화면에서 입력과 추천 목록이 함께 보이는지, 공지의 터치 hover·탭 전환 중 애니메이션 진행과 TV 예시의 1920×1080/1280×720 비율·문자 크기·입력 X도 브라우저에서 확인했다. 실제 iPhone의 시스템 키보드·제스처, 실제 TV 리모컨/가독성은 실기기 확인이 필요하다.

이 환경에서 Supabase CLI는 읽기 전용 홈 초기화 오류가 있어 native MCP migration을 사용했고, 서버가 부여한 실제 버전으로 로컬 마이그레이션 파일을 맞췄다. 비공개 Sites 미러는 소유자 전용 상태를 확인했으나 소스/배포 helper가 이 실행환경에 없으므로 갱신하지 않았다. 회원 서비스 배포와 별개이며 공개 범위는 바꾸지 않았다.
